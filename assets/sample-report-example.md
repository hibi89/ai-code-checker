# AI 코드 검수 리포트 예시

> **합성 코드로 만든 서식 예시입니다.** 실제 고객 저장소를 검수한 결과도, 실제 Gemini 응답도 아닙니다. 파일명, 프로젝트, 발견 항목은 모두 가상입니다.

## 한눈에 보기

- 검수 대상: `demo/invoice.py` (가상 Python 예제, 8줄)
- 검수 범위: 코드 근거를 설명하는 결과 리포트의 형식 예시
- 우선 확인 항목: HIGH 1건, MEDIUM 1건
- 코드 실행, 테스트 실행, 배포 환경 확인: 하지 않음

## 먼저 확인할 항목

### HIGH - SQL 쿼리에 사용자 입력이 문자열로 들어갑니다

- 위치: `demo/invoice.py:2-3`
- 근거: `query = f"SELECT * FROM invoices WHERE id = {invoice_id}"`
- 영향: `invoice_id`를 안전한 정수로 제한하지 않으면 입력값이 SQL 문법에 섞여 의도하지 않은 행 조회나 쿼리 변형에 이용될 수 있습니다.
- 권고: DB 드라이버의 파라미터 바인딩으로 쿼리를 실행하고, 요청 입력도 필요한 형식으로 검증하세요.
- 확인 수준: 합성 예시 내용. 실제 프로젝트의 DB 드라이버와 호출 맥락은 검수하지 않았습니다.

### MEDIUM - 현재 사용자의 청구서인지 확인하는 조건이 보이지 않습니다

- 위치: `demo/invoice.py:1-8`
- 근거: 함수는 `current_user_id`를 받지만 조회 조건에는 `owner_id`가 포함되지 않습니다.
- 영향: 호출 경로에서 별도 권한 검사가 없다면 다른 사용자의 청구서가 반환될 수 있습니다.
- 권고: 쿼리에 소유자 조건을 포함하고, 사용자 A가 사용자 B의 식별자로 요청할 때 거부되는 테스트를 추가하세요.
- 확인 수준: 호출부와 인증 미들웨어가 제공되지 않은 합성 예시이므로 권한 누락 여부는 조건부 위험입니다.

## 다음 작업 순서

1. 파라미터 바인딩을 적용합니다.
2. 사용자 소유권 조건을 조회에 포함합니다.
3. 정상 사용자와 다른 사용자 식별자로 각각 회귀 테스트를 추가합니다.
4. 수정 후 변경된 함수와 호출부를 다시 검수합니다.

## 범위와 한계

이 예시는 AI 보조 검수 결과를 사람이 원본 코드와 대조해 전달하는 서비스의 결과물 형식만 보여줍니다. 실제 판매 시에는 접수한 프로젝트의 파일·줄·근거를 확인해 결과를 작성합니다. 테스트 실행, 침투 테스트, 서버 설정 확인, 보안 인증 또는 무결점 보증은 포함하지 않습니다.
