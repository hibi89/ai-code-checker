# Code Checker — tagged upstream Tcl/Tk license equality review

This is an optional offline evidence step, **not a release or license compliance approval**. It compares separately supplied exact local Tcl and Tk `license.terms` bytes with version-pinned upstream Git blob SHA-1 values, and binds the evidence to the frozen EXE SHA-256 recorded in the runtime receipt.

## Verified upstream baselines

| Source | Official original | Git blob SHA-1 |
| --- | --- | --- |
| Tcl 8.6.15 | https://github.com/tcltk/tcl/blob/core-8-6-15/license.terms | `d8049cd9e7ca055f7e584a76f88861a294b30c9c` |
| Tk 8.6.15 | https://github.com/tcltk/tk/blob/core-8-6-15/license.terms | `01264352c87ca7e34771bd1ee18bed5201ef139f` |
| Tcl 8.6.18 | https://github.com/tcltk/tcl/blob/core-8-6-18/license.terms | `d8049cd9e7ca055f7e584a76f88861a294b30c9c` |
| Tk 8.6.18 | https://github.com/tcltk/tk/blob/core-8-6-18/license.terms | `01264352c87ca7e34771bd1ee18bed5201ef139f` |

Git blob SHA-1 includes Git's blob header; it is **not** SHA-256 and not the bare SHA-1 of the text. This tool supports exactly these verified runtime patchlevels and rejects any others. It does not make assumptions about 8.6.16, 8.6.17, or vendor-modified builds.

## Integrated CI candidate check (not customer release)

Windows candidate CI now compares the **same generated EXE** and live frozen Tcl/Tk patchlevel receipt against exact original `license.terms` bytes staged from that Windows Python installation. The byte identity must match the pinned upstream Git blob for each exact patchlevel. The check fails closed on missing, ambiguous, modified or unsupported originals and writes only local metadata to `.build-windows/tcltk-upstream-installed-source-match.json`. No original license text, EXE or customer code is uploaded as a public artifact.

This only proves that the **installed build-runtime source candidates** match the upstream license originals. It does **not** prove that the embedded native libraries belong to those builds or that their binary redistribution, copyright attributions and other third-party NOTICE obligations are cleared. The 71 component review and owner Windows acceptance remain blocked.

## Developer-local usage

Requires an EXE and its **actual frozen runtime receipt** as generated by [PR #60](https://github.com/hibi89/ai-code-checker/pull/60). That PR must pass Windows CI before being accepted; the tool can be developed and unit-tested separately in the meantime. After obtaining the applicable two exact, unmodified upstream originals locally:

```powershell
python -m scripts.verify_upstream_tcl_tk_license `
  --exe dist-windows/CodeCheckerOffline.exe `
  --runtime-receipt .build-windows/runtime-version-receipt.json `
  --tcl-original PATH_TO_TCL_LICENSE.terms `
  --tk-original PATH_TO_TK_LICENSE.terms `
  --out .build-windows/upstream-tcltk-license-match.json
```

The output must not already exist. The script performs no network access, automated license downloads, extraction or customer-code reads, and emits only EXE digest, version, Git blob identifiers and conservative release-block flags. The actual original texts stay local.

**What is and is not established:** If this step succeeds, the two supplied local texts match the pinned *upstream* originals, and the receipt's EXE hash matches the supplied executable. The receipt itself is **not independently cryptographically authenticated**; source-license equality proves neither the vendor/owner of an included DLL nor an approved redistribution NOTICE. A separate human review must verify actual bundled component versions, derivatives, vendor modifications, additional Tcl/Tk extensions, CPython/PyInstaller/VC obligations and the 71 other unresolved EXE entry classifications.

No feature branch, test or metadata artifact may set `third_party_notice_ready`, `license_compliance_certified` or `customer_release_ready` to true. Normal buyer Windows GUI, SmartScreen/Defender, OS packet capture and Korean PDF visual acceptance remain UNVERIFIED.

**Decision:** A generic copyright notice pasted into the ZIP was rejected due to wrong-release and missing-third-party risk. Byte matching to two exact upstream Git blobs costs no API calls, is safer and auditable, but still leaves final legal/commercial signoff to the owner.
